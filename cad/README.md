# CAD and simulation

Everything here is generated from `analysis/results.json` and `cad/hardware.json`. After changing the sizing or the hardware spec, re-run the build and the CAD follows. Nothing is modelled by hand.

## Files

| File | Purpose |
|---|---|
| `params.mjs` | Converts the sizing results and `hardware.json` into build parameters, fastener definitions, the fastener schedule, every component placement (position + rotation matrix) and the exploded layout → `params.txt` |
| `hardware.json` | Machine-readable twin of `docs/research/hardware-spec.md`: fasteners, nuts, washers, inserts, fits, general tolerances (same IDs as the spec and the drawings) |
| `BuildVtol.cs` | SOLIDWORKS API builder: 77 part files, the 397-component `VTOL_Concept.SLDASM` (STEP, EASM), `VTOL_Exploded.SLDASM`, interference detection and mass roll-up → `verification.txt` |
| `build.ps1` | Runs `params.mjs`, then compiles and runs the builder, mesh export, drawings and renders (needs SOLIDWORKS 2025 + .NET Framework 4 `csc`) |
| `Drawings.cs` | Builds drawing DBF-DRW-001 rev E (nine ANSI B sheets, see below) with driven dimensions, tolerances and fits from `params.txt` (note text included: every size that follows the sizing is read from `params.txt`); zoned layout with a self-check of overlaps (`drawings/layout-check.txt`); exports `.SLDDRW`, a vector PDF and sheet PNGs to `drawings/`. `Drawings.exe model drawings params.txt 2,3` builds only the listed sheets as `probe_*` files for layout iteration |
| `Shared.cs` | Compiled into `BuildVtol.exe`, `Drawings.exe`, `Sim.exe` and `Thermal.exe`: `ParamsFile`, the one C# reader of `params.txt`, and `Geom`, the one C# implementation of the NACA 4-digit section and the pod profile (constants read back from `params.txt`, see "Single sources" below) |
| `SharedTest.cs` | Parity test of `Shared.cs` against the inline code it replaced (bit-exact sections, pod radii and parsed parameters; no SOLIDWORKS). `build.ps1` compiles and runs it before every build; by hand: `csc /nologo /out:%TEMP%\SharedTest.exe cad\Shared.cs cad\SharedTest.cs && %TEMP%\SharedTest.exe cad\params.txt` |
| `ExportMesh.cs` | Exports each part as a binary STL (metres, part frame) plus colour and description → `mesh/`; `review/mesh.mjs` packs them (one pre-rotated mesh per part orientation) for the interactive viewer in the review page |
| `Snap.cs` | Saves iso/top/side/front PNGs of the assembly → `images/` |
| `BuildFigs.cs` | Step figures for the build manual: per figure in `docs/build/figs.txt`, shows the parts a step fits (orange, with their fasteners in blue) among the parts already built, renders and crops → `docs/build/img/*.jpg` (assembly closed unsaved) |
| `Sim.cs` | SOLIDWORKS Simulation studies → `sim/results.txt`, plots, and `sim/*.SLDPRT` with the studies saved inside (re-run 2026-10-25 on the CAD rev D / v0.4 inputs, see below) |
| `ListDocs.cs` | Lists open SOLIDWORKS documents; `ListDocs.exe close` closes files under this folder, `close untitled` also discards unsaved new documents |
| `Inspect.cs` | Lists a part's feature tree, bodies, volume and box (debugging aid) |
| `TlbImp.cs`, `Probe.cs` | Tools used to inspect the Flow Simulation API and add-in availability |
| `model/` | Generated parts, `VTOL_Concept.SLDASM`, `.STEP`, `.EASM`, `VTOL_Exploded.SLDASM` |
| `verification.txt` | Interference report, component counts, cosmetic-thread count, mass roll-up (generated by each build) |

## Model content (v0.4, CAD model rev D 2026-10-25, hardware spec of 2026-10-21)

- **Sizing inputs (aero):** `analysis/sizing.mjs` now uses the aerodynamic build-up in `analysis/aero/aero_results.json`: CL_max 1.114 (critical-section, trimmed; `analysis/results.json` base.CLmax), clean CD0 0.0266 (faired legs), rotor-unit CdA 0.00222 m², boom CdA 0.00167 m², and a pod neutral-point shift of −5.57 % MAC. Result (re-sized 2026-10-25 to the 11.75 m/s design stall, `docs/research/stall-margin.md`; `analysis/results.json` generated 2026-10-25, base.Vs 11.75): MTOW 6.55 kg, wing 0.682 m² (chord 284.2 mm, AR 8.45), cruise 337 W, 12.3 min of cruise available, static margin 11.5 % at the 28 % CG (NP 39.5 % MAC) and 4.9 % at the no-payload CG (`analysis/results.json` C0 sized and cg). CAD rev D is this geometry; rev C was the R11 re-size (chord 266.6 mm, S 0.640 m², MTOW 6.45 kg). **Operating rule:** with no payload fly with 0.5 kg of ballast in the payload bay so the CG stays at 28 % MAC (note 5 on the GA sheet).
- **Wing:** NACA 2415 panels, chord from the sizing. A 26 % chord aileron (2 % hinge gap) runs along the outer 55 % of span. The 25.4 mm spar socket is bored 0.8 m from the root at 30 % chord. Pockets are cut for every bonded hardpoint: spar collar (front clamp inserts), rear hardpoint plate (80 % chord), aileron servo tray, root tongue, and (left) the pitot clamp; the ailerons carry a horn-hardpoint pocket.
- **Wing root and joiner:** the saddle carries the root section across the pod and has two 6 mm side tabs screwed to the pod (4 × M3 × 12 into inserts). The 0.76 m joiner is a **slip fit** in the saddle and the sockets (FT01/FT06): it slides out so the pod transport piece stays inside the R4 envelope, and with both panels bolted on it is captured between two printed stop discs bonded 300 mm inside the sockets. Each panel is held by one M5 × 20 button screw through a printed bolt pillar in the saddle and a root tongue bonded into the panel, into an M5 nylock (J10). The pillar is the full section height at 70 % chord (26.0 mm in rev D); `params.mjs` deepens the head spot-face from 1.0 mm in 0.5 mm steps until the nut pocket (screw end 0.5 past the nylock) stays at or below the tongue-slot floor: rev D spot-face Ø10.3 × 2.0, pocket 8.2 AF × 9.6 under a 9.6 mm slot floor (with the old 1.0 spot-face the pocket would be 10.6 deep and the nylock would sit 0.7 mm inside the tongue).
- **Tail:** NACA 0009 stabiliser seated on the tail-clamp tops (span = boom spacing + 50 mm to cover the fin-shoe flanges), separate 30 % chord elevator (4 mm from each fin), lofted fins (65 % tip chord) **with 30 % chord rudders** hinged with the same 2 % gap as the ailerons (BOM servos S5/S6; rudder sizing follows the elevator and aileron chord ratios, hardware-spec.md C6). Fins sit in printed root shoes whose flanges are screwed through crush sleeves in the stabiliser into the tail clamps (J09): four screws remove the tail.
- **Booms:** 6061-T6 1.000 × 0.035 in front booms (991.0 mm) butt against the rear stubs (485.9 mm) at the rear motor centre, inside the rear motor mount, over a printed splice plug with two M3 × 40 cross-bolts (J04). The front and rear lengths are generated by `analysis/sizing.mjs geometry()` (no overlap).
- **Printed clamps (all 46 mm wide, bore 25.6, 1.2 mm split gap):** motor mounts (PA6-CF) split into an upper half with the 4.5 mm motor floor and a lower cap, so the motor screws go in from inside the bore; front and rear boom clamps (lower halves bolt through the upper halves into the wing hardpoint inserts); gear clamps with a blind leg socket and a leg cross-bolt; tail clamps. Every counterbore, insert hole and nut pocket is at the spec's size.
- **Propulsion:** X4110S motors with their real bolt patterns (base 4 × M3 on Ø25, max depth 3.3; hub 4 × M3 on Ø12), lift props with 4 mm bore and 2 × 3.2 holes on 12 mm, prop holding plates, the pusher's bolt-on M6 adapter, prop washer and bullet nut; PA6-CF pusher cup in the pod tail ring with four radial screws. The spinner of rev A is gone (the bullet nut is the real part).
- **Controls:** five EMAX ES3005HV servos on one printed L-tray design (aileron servos in wing pockets, elevator and rudder servos on the stabiliser top), kit nylon horns with backplates or bonded hardpoints, and 2-56 pushrods cut to the CAD lengths (ailerons 48 mm, elevator 40 mm, rudders 102 mm at rev D; `params.txt` rodAileron / rodElevator / rodRudder).
- **Gear:** four 205 mm legs in the gear-clamp sockets with dome feet, each with a printed 3:1 teardrop fairing (chord 81.6, 170 mm long, vase-mode wall, taped at the clamp; aero drag build-up; `params.txt` fairChord / fairLen). Pusher prop ground clearance 42 mm.
- **Pod:** solid foam body with the wing-root slot, battery bay and tray, avionics bay with the FC tray and the CoreWing envelope, canopy pocket with a 2 mm hatch flange (2 screws) and front tongue, and the tail ring bore.

## Fastener modelling

Every screw, nut, washer and heat-set insert in `hardware.json` is a part generated at the vendor's maximum dimensions (`params.mjs` `fast=` lines → `BuildVtol.FastenerPart`): ISO 4762 socket heads with hex sockets, ISO 7380 button heads, the kit's M2 × 14 pan heads (head EST), DIN 985 nylocks (hex + collar), DIN 934 M2 nuts, DIN 125 washers, ruthex RX-M3x5.7 inserts (knurl shown as two bands), the motor-supplied M3 × 8 adapter screws (F13, length EST) and the M6 bullet nut. Each instance is placed at its joint by a rigid transform (rows of the 3 × 3 matrix in the `comp=` line are the images of the part axes), with holes in the parent parts at the spec's clearance/insert diameters (printed model value = ISO 273 normal + 0.2). Cosmetic threads (InsertCosmeticThread3) are on the shank of every screw, the bores of the nuts and the insert and the M6 adapter (17 of the 18 fastener part files; the washer has none). Two spec values changed because the model showed they cannot be built: F05 is M3 × 30 (its nut and head must clear the leg tube in the gear clamp) and the motor counterbores are Ø7.5 (the Ø7.0 washer does not fit Ø6.5); both are recorded in `hardware.json` and in the spec's CAD implementation notes. Counts per aircraft: 139 screws (F01 20, F02 36, F03 16, F04 8, F05 4, F06 4, F07 11, F08 4, F09 2, F10 20, F11 10, F13 4), 40 nuts (N01 8, N02 2, N03 30, N04 1), 28 washers, 67 inserts — the same as hardware-spec.md §6. Heat-set inserts sit in Ø4.0 holes with their 4.6 OD, so interference detection reports them as intended press fits (FT08); they are listed separately in `verification.txt`. Last run (CAD rev D, 2026-10-25): 397 components, 277 interferences of which 193 are the insert press fits (1.40 cm³) and 84 are slivers totalling 0.45 cm³ (flat printed bases and screw heads against curved foam surfaces, the clevis forks around the horn uprights, numerical slivers at the spar sockets; the largest is 102 mm³, a rudder clevis around its horn upright (Control_Horn-1 × Pushrod_Rudder-1, the same since rev B); all others ≤ 26 mm³; no nylock × root-tongue contact at the wing bolt). Modelled mass 6.36 kg (fasteners 228 g, printed parts 1.38 kg, tubes 1.67 kg, foam 0.95 kg without skins, vendor masses 2.12 kg) against the sizing MTOW 6.55 kg, which also carries wiring, ESCs, skins, avionics and the payload allowance.

Mass: `verification.txt` rolls up every part as volume × density (6061 from the SOLIDWORKS library; A2 stainless, brass, PETG, PA6-CF and nylon densities EST; XPS 32 kg/m³ from the sizing) or the vendor mass (motors, battery, servos, props, FC). `analysis/sizing.mjs` does not track fastener mass as an item (it sits inside the clamp and mount allowances), so the fastener total is reported there for the team rather than added to the MTOW.

## Single sources (code review 2026-10-25, "one geometry described in several places")

The wing/tail section family and the fuselage-pod profile used to be re-typed in six places (two different trailing-edge coefficients, `cad/params.mjs`, `BuildVtol.cs`, `Drawings.cs`, `analysis/aero/common.py`, `docs/build/templates/make_templates.py`) and `params.txt` was parsed by six different readers. They are now defined once and read through one module per language; the refactor changed no output (all regenerated outputs byte-identical, see `SharedTest.cs` and the parity notes in `analysis/README.md`).

| What | Single source | Readers |
|---|---|---|
| Section family: NACA 24xx camber (`m` 0.02, `p` 0.4; `t` = sizing `tc`), NACA 0009 tail, TE coefficients `teCad` −0.1015 / `teAero` −0.1036, pod profile (`noseX` 0.45, `L` 0.85, `R` 0.08, `tailR` 0.03, `noseA` 0.22, `parallelTo` 0.50) and the reference formulas | `analysis/geometry.mjs` (a leaf module: imported by `analysis/sizing.mjs`, `analysis/tradestudy.mjs` and `cad/params.mjs`; the sizing never reads `params.txt`, which is generated from it) | — |
| The same constants as data | `params.txt` keys `foilWing`, `foilTail`, `foilTE`, `podProfile` (text records `label\|name=value...`, written by `params.mjs`; `fusL`, `fusR`, `tailR`, `tc` stay numeric keys) | `analysis/geom.py` (Python: `read_params`, `naca4_surfaces`/`naca4_outline`, `pod_radius`; used by `analysis/aero/common.py` and so every aero script, and by `make_templates.py`), `cad/Shared.cs` (C#: `ParamsFile.Load`, `Geom.WingSection`/`TailSection`/`Naca`/`NacaYt`/`NacaYc`/`PodRadius`; used by `BuildVtol.cs`, `Drawings.cs`, `Sim.cs`, `Thermal.cs`) |
| `params.txt` parsing rules | documented in `analysis/geom.py` and `cad/Shared.cs` (trim; blank lines ignored; a line without `=` or a repeated key is an error; `comp=`/`xcomp=` are records, everything else a scalar) | the two readers above; `review/build.mjs` keeps its own numeric-only reader and skips the text records |

**Trailing edge.** Two coefficients remain in use on purpose: the CAD, drawings and `params.txt` stations use the original open-TE polynomial (−0.1015, TE thickness 0.0021 c = 0.6 mm at the 284 mm chord — the better model of a hot-wired XPS core with a tape skin), while the aero package (SU2 meshes, NeuralFoil) and the hot-wire templates use the closed-TE value (−0.1036; a closed contour for meshing and a clean wire exit). Forward of 70 % chord the two differ by < 0.05 mm. Unifying them would change either the CAD coordinates or the aero/template outputs, so both are named at the single source (`FOIL.teCad`, `FOIL.teAero`) and the choice per consumer is explicit. Recommendation for the next template revision: move `make_templates.py` onto `teCad` so the templates match the drawn section (changes the SVG/CSV by ≤ 0.6 mm at the TE only).

`Sim.cs` and `Thermal.cs` are built by hand with `Shared.cs` on the command line, e.g. `csc /nologo /platform:x64 /out:cad\Sim.exe /r:"<redist>\SolidWorks.Interop.sldworks.dll" /r:"<redist>\SolidWorks.Interop.swconst.dll" /r:cad\SolidWorks.Interop.cosworks.dll cad\Sim.cs cad\Shared.cs`.
